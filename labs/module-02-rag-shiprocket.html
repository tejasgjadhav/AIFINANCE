Building RAG for Shiprocket IPO DHRP

We build a RAG pipeline over the 543-page Shiprocket draft prospectus from SEBI. You ask a question in plain English and get a short answer with page numbers you can verify.

PDF → LlamaIndex splits and embeds → ChromaDB stores the chunks → Codex writes the answer

01Why we built it

Nobody reads 543 pages to answer one question. You also cannot paste 543 pages into a normal AI chat, because the chat cannot hold that much text. There is a bigger problem than size: an AI answering from its own memory can invent numbers, and an invented number in an IPO note is a career risk.

RAG stands for Retrieval-Augmented Generation. It fixes both problems in two moves. First it retrieves the few paragraphs in the document that match your question. Then the AI receives only those paragraphs and writes the answer from them, with page numbers. If the retrieved paragraphs do not contain the answer, the AI says so. It does not guess.

02The components, one by one

  1. The PDF. This is the source document. We downloaded the Shiprocket UDRHP from the SEBI filing page and saved it as data/shiprocket-udrhp.pdf. Everything the system says must come from this file.
  2. uv. This is a free tool that installs Python and Python libraries. We used it because the laptop only had an old Python 3.9, and uv fetched Python 3.12 in seconds without admin rights.
  3. The virtual environment. This is an isolated box for our libraries. It keeps the project's installs separate, so nothing else on the machine breaks.
  4. LlamaIndex. This is the pipeline manager. It loads the PDF, cuts it into 885 chunks, sends each chunk to the embedding model, and hands the results to the database. It also does the retrieval when you ask a question.
  5. The embedding model. BAAI/bge-small-en-v1.5 is a free 130 MB model that runs on the laptop with no API key. It turns each chunk into a vector, which is a list of 384 numbers. Chunks with similar meaning get similar numbers. This is how the computer finds relevant text by meaning instead of by keywords.
  6. ChromaDB. This is the vector database. It stores all 885 chunks with their vectors in the chroma_db/ folder on disk. When you ask a question, it returns the nearest chunks in milliseconds. Because it lives on disk, we embed the document once and query it forever.
  7. Codex CLI. This is the writer. It receives your question plus the retrieved chunks as one prompt and writes the final answer. It runs on a ChatGPT login, so it needs no API key either.

03The five Python libraries

  • llama-index-core — the engine. It runs the load, split, embed and store pipeline.
  • llama-index-readers-file — the reader. It reads the PDF and keeps each page number as metadata.
  • llama-index-embeddings-huggingface — the embedder. It downloads the free embedding model and runs it locally.
  • llama-index-vector-stores-chroma — the bridge. It lets LlamaIndex write into ChromaDB and read back from it.
  • chromadb — the database. It stores the chunks and finds the nearest ones.

05Script 1: ingest.py builds the database

The script runs five steps in order: load, split, embed, store, run. You run it once.

"""Build the vector store for the Shiprocket DHRP.

Pipeline: PDF -> LOAD -> SPLIT -> EMBED -> STORE.
LlamaIndex does the loading, splitting and embedding.
ChromaDB stores the chunks with their vectors, on disk.

Run from this folder:  .venv/bin/python ingest.py
"""

import chromadb
from llama_index.core import SimpleDirectoryReader, StorageContext, VectorStoreIndex
from llama_index.core.node_parser import SentenceSplitter
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.chroma import ChromaVectorStore

# Step 1 - LOAD. One Document per PDF page, with the page number kept as metadata.
documents = SimpleDirectoryReader("data", exclude_hidden=False).load_data()
print(f"Step 1: loaded {len(documents)} pages from data/")

# Step 2 - SPLIT. Each page becomes overlapping chunks of ~1024 tokens.
# The overlap stops a sentence being cut in half at a chunk border.
splitter = SentenceSplitter(chunk_size=1024, chunk_overlap=200)

# Step 3 - EMBED. A free local model turns each chunk into a 384-number vector.
# No API key: the model (~130 MB) downloads once from Hugging Face, then runs offline.
embed_model = HuggingFaceEmbedding(model_name="BAAI/bge-small-en-v1.5")

# Step 4 - STORE. ChromaDB keeps chunks + vectors in the chroma_db/ folder,
# so ingestion runs once and every later query just reads from disk.
db = chromadb.PersistentClient(path="chroma_db")
collection = db.get_or_create_collection("shiprocket_dhrp")
vector_store = ChromaVectorStore(chroma_collection=collection)
storage_context = StorageContext.from_defaults(vector_store=vector_store)

# Step 5 - RUN the pipeline: split every page, embed every chunk, write to Chroma.
index = VectorStoreIndex.from_documents(
    documents,
    storage_context=storage_context,
    transformations=[splitter],
    embed_model=embed_model,
    show_progress=True,
)

print(f"Done. Chroma collection 'shiprocket_dhrp' holds {collection.count()} chunks.")
Run it
.venv/bin/python ingest.py

06Script 2: query_test.py proves the retrieval works

This script embeds your question with the same model and asks ChromaDB for the 3 nearest chunks. It uses no AI writing and no API key.

"""Sanity check: pull the 3 most relevant chunks for a question.

Pure retrieval - no LLM and no API key needed.

Run from this folder:  .venv/bin/python query_test.py "your question"
"""

import sys

import chromadb
from llama_index.core import VectorStoreIndex
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.chroma import ChromaVectorStore

question = " ".join(sys.argv[1:]) or "What are the main risk factors for Shiprocket?"

# Same embedding model as ingest.py - the question must live in the same vector space.
embed_model = HuggingFaceEmbedding(model_name="BAAI/bge-small-en-v1.5")

# Reopen the store built by ingest.py. Nothing is re-embedded here.
db = chromadb.PersistentClient(path="chroma_db")
collection = db.get_or_create_collection("shiprocket_dhrp")
vector_store = ChromaVectorStore(chroma_collection=collection)
index = VectorStoreIndex.from_vector_store(vector_store, embed_model=embed_model)

retriever = index.as_retriever(similarity_top_k=3)
print(f"Question: {question}\n")
for i, node in enumerate(retriever.retrieve(question), 1):
    page = node.metadata.get("page_label", "?")
    print(f"--- Result {i} | page {page} | score {node.score:.3f} ---")
    print(node.text[:400].strip())
    print()

07Script 3: ask.py writes the answer through Codex

Install the Codex CLI once and log in with a ChatGPT account:

npm install -g @openai/codex
codex login

The script retrieves the 5 nearest chunks, builds one prompt with the chunks inside it, and sends the prompt to Codex. The prompt tells the model to use only the retrieved context.

"""Ask the Shiprocket DHRP a question and get a written answer.

Retrieval: LlamaIndex embeds the question and ChromaDB returns the
nearest chunks. That part is local and free.
Generation: the chunks and the question go to an LLM as one prompt.

Two modes:
  .venv/bin/python ask.py "your question"          -> answers via the Codex CLI
  .venv/bin/python ask.py --print "your question"  -> prints the prompt instead,
                                                      to paste into any free AI chat
"""

import subprocess
import sys

import chromadb
from llama_index.core import VectorStoreIndex
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.chroma import ChromaVectorStore

args = sys.argv[1:]
print_only = "--print" in args
args = [a for a in args if a != "--print"]
question = " ".join(args) or "What are the main risk factors for Shiprocket?"

# Step 1 - RETRIEVE. Same embedding model as ingest.py, top 5 chunks.
embed_model = HuggingFaceEmbedding(model_name="BAAI/bge-small-en-v1.5")
db = chromadb.PersistentClient(path="chroma_db")
collection = db.get_or_create_collection("shiprocket_dhrp")
index = VectorStoreIndex.from_vector_store(
    ChromaVectorStore(chroma_collection=collection), embed_model=embed_model
)
nodes = index.as_retriever(similarity_top_k=5).retrieve(question)
print(f"Retrieved {len(nodes)} chunks from pages: "
      f"{[n.metadata.get('page_label', '?') for n in nodes]}\n", flush=True)

# Step 2 - BUILD the prompt. The context travels inside the prompt itself,
# so the LLM answers from the prospectus and not from its own memory.
context = "\n\n".join(
    f"[{i}] (page {n.metadata.get('page_label', '?')})\n{n.text.strip()}"
    for i, n in enumerate(nodes, 1)
)
prompt = f"""You are a financial analyst. Answer the question using ONLY the context below, which comes from the Shiprocket Limited draft red herring prospectus (UDRHP). Cite the page number after each fact, like (p. 54). If the context does not contain the answer, say "The retrieved sections do not answer this." Do not use any other knowledge.

CONTEXT:
{context}

QUESTION: {question}"""

# Step 3 - GENERATE.
if print_only:
    print(prompt)
    sys.exit(0)

# codex exec runs one non-interactive turn and prints the answer.
# It uses the ChatGPT login stored by `codex login`; no API key is needed.
subprocess.run(["codex", "exec", prompt])

08Where to go from here

Change chunk_size in ingest.py to 512 and rebuild, then compare the retrieval quality. Raise similarity_top_k in ask.py from 5 to 10 and watch the answers gain detail. Swap the document: every DHRP on the SEBI site has objects of the issue, risk factors, promoter details and litigation, so your ten test questions transfer to any IPO you are studying.
