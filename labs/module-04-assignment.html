Connect, Retrieve, Backtest

The class is split into six groups. Every group does all three parts. The assignment carries 10 marks and is graded in a two-hour live review, not on the slides.

Part 1 MCP → Part 2 RAG → Part 3 Backtest → one hour coding live → one hour demonstrating
Read this first. You are not asked to produce a profitable strategy. You are asked to produce a result you can defend. A group that reports "we did not hit the target, and here is the evidence" scores full marks on Part 3. A group that reports a hit it cannot reproduce scores zero on Part 3.

01How the assignment is organised

  • Six groups. Group sizes are announced in class. Each group works on all three parts.
  • Ten marks in total. Part 1 carries 3, Part 2 carries 3, Part 3 carries 3, and the demonstration carries 1.
  • We use Codex. Codex is the client for every part of this assignment. Claude Code is accepted as an alternative, and section 02 gives the route for both.
  • The review is live. You get one hour to code in front of the faculty and one hour to demonstrate. Section 07 explains what each hour is for.
  • Everything must be free. No group is expected to pay for a data feed, an API plan or an AI subscription. Every route below has a free tier.
  • Nothing goes live. Use a paper account, a sandbox key or a read-only connection. No group places a real order. Any group that trades real money on this assignment scores zero on Part 1.
  • Each group gets its own instrument set. The table in section 05 gives every group its own chart instruction and its own backtest universe, so six different systems are demonstrated in class.

02Part 1 — Install an MCP and drive a chart3 marks

Module 3 taught what MCP is. This part asks you to run one. You will not write a configuration file. You will find the MCP, tell Codex to install it in one plain English line, and then ask it to do something on a chart.

The method, in three steps

  1. Search for it. Type what you want into Google, followed by the word MCP. Example: TradingView MCP. Read the top result and confirm that the server exists and is free.
  2. Set up the thing it drives. An MCP that drives TradingView needs TradingView on the machine. Download the TradingView desktop app and complete the free sign-up. Log in and leave a chart open. Do this before you talk to Codex, because the server has nothing to connect to otherwise.
  3. Tell Codex in one line. Open Codex and type the instruction as a sentence. Codex installs the server and does the work.
The line we typed in class
Install TradingView MCP and draw open high low on the Bitcoin chart for intraday.

That is the whole instruction. There is no config file in it, no path and no command. Codex finds the server, installs it, connects to the app that is already running, and draws on the chart. Watch what it asks you before it acts, and approve each step.

What your group does

  1. Run the search and write down the server you picked, where it came from and who publishes it.
  2. Install the app and log in on a free account. Record which version you installed.
  3. Give Codex your group’s one-line instruction from the table in section 05. Type it as a sentence, not as a command.
  4. Let it draw. The chart must change on screen. A text answer about what the levels are does not count.
  5. Ask one question the tool must answer, not the model. Example: "What is the last traded price on this chart and what is the timestamp on it?" Then check that price against the exchange or the exchange website yourself.
  6. Write down the delay. State whether your feed is real time or delayed, and by how many minutes. A free account is usually delayed. Saying so is part of the mark.

What you show in the review

  • Say which search you ran and which server you chose.
  • Read out the exact sentence you gave Codex.
  • Open Codex on screen with the server installed and its tools listed.
  • Show the chart with your drawing on it, live.
  • Tell us in six lines what the server is, what it drew, what the delay is, and the one thing that broke on the way.
Never paste a live API key into a chat window or a slide. TradingView needs only a free login, so most groups will not touch a key at all. Any group that takes the broker route keeps its keys in a local file and in an environment variable. Close the file before you share your screen. A key that appears on screen loses the Part 1 mark, and you must rotate that key the same day.

03Part 2 — RAG over the three latest IPO prospectuses3 marks

Module 2 built a question and answer bot over the Shiprocket DRHP. This part repeats that work on three documents at once, and on documents nobody has read for you.

The stack is fixed

Every group builds the same pipeline, so the six results are comparable and the marker can read any group’s code.

  • LlamaIndex loads the prospectus, splits it into chunks and creates the embeddings.
  • ChromaDB stores the vectors.
  • The LlamaIndex retriever fetches the chunks that answer each question.
  • Codex writes the code. Tell it the stack in your first sentence, the same way you told it the MCP.

Do not substitute another framework or another database. A group that ships LangChain or FAISS instead loses one mark on Part 2, however well it works.

Pick the documents

  • Take the three most recent mainboard IPOs listed on the NSE or the BSE as of the day your group starts.
  • Write down each company name, the listing date and the exchange. Those three dates fix your document set for the rest of the assignment.
  • Download the RHP or the DRHP for each company from the SEBI website or the exchange filing page. Note the file name, the number of pages and the date on the cover.
  • Do not use a news summary or a broker note in place of the prospectus. The prospectus is the source.

Answer these six questions for each company

  1. Issue size. How large is the issue, and how does it split between the fresh issue and the offer for sale?
  2. Objects of the issue. What does the company say it will do with the fresh issue money?
  3. Financials. Revenue from operations and profit after tax for each of the last three financial years.
  4. Risk factors. Three risks that are specific to this company. A risk that would apply to any listed company does not count.
  5. Promoter holding. The promoter shareholding before the issue and after the issue.
  6. Peers. The peer group the company itself names, and how the price band compares with the peer median on the multiple the prospectus uses.
Every answer carries a page number. Six questions across three companies come to eighteen answers, so the table carries eighteen citations. The marker will open your prospectus at three of those pages at random. If the number is not on the page you cited, that answer is wrong even if the number is right.

What you show in the review

  • Name the three companies, their listing dates and the prospectus files you used.
  • Show your LlamaIndex settings on screen: chunk size, chunk overlap, the embedding model, and how many chunks the retriever returns per question.
  • Show the ChromaDB collection and how many vectors it holds.
  • Put the table of 18 answers with page citations on a slide.
  • Tell us one question your bot got wrong, the wrong answer it gave, and why the retrieval missed.

04Part 3 — Backtest against a hard target3 marks

Build a momentum strategy on your assigned universe and test it against a target of a 75% win rate and a 5% net monthly return. Net means after costs. The target is deliberately hard. Your job is to measure the distance to it and to report that distance honestly.

The rules of the test

  1. Window. Use the last 24 completed months of daily data, ending on the last completed session before you start.
  2. Split the window. Use the first 12 months to choose your parameters. Freeze those parameters. Then run the last 12 months once, and do not go back and change anything. Report both halves separately.
  3. Signal. A momentum rule of your choosing. Rank by trailing return, or use a moving average crossover, or use RSI. Write the rule in one sentence before you code it.
  4. Timing. Generate the signal on a closed bar. Enter on the next session. A backtest that enters on the same bar that produced the signal is looking into the future and scores zero.
  5. Costs. Run the same strategy three times, at 25, 50 and 100 basis points round trip. Report all three.
  6. Trade count. Report the number of trades. A win rate computed on fewer than 30 trades is not evidence, and you should say so in your own report.
  7. Benchmark. Compare the net result with buying and holding the index for your universe over the same 24 months.

What you report

NumberWhat it means
Win rateWinning trades divided by total trades, in sample and out of sample, stated separately
Net monthly returnThe monthly return series after costs, at each of the three cost levels
Months above 5%How many of the 24 months cleared the target, and how many did not
Maximum drawdownThe largest peak to trough fall in the equity curve
Sharpe ratioComputed on the net series, with the risk-free rate you used stated
TradesThe count, and the average holding period in sessions
VerdictOne sentence: was the 75% and 5% target met, and on which half of the data
The target is probably out of reach, and that is the lesson. A win rate of 75% and a net 5% a month is roughly an 80% annual return with almost no losing trades. Very few strategies survive that test once costs are charged. If your first result clears the target easily, the most likely explanation is a bug: a same-bar entry, a survivorship-biased universe, or parameters fitted on the same data you tested. Look for the bug before you report the win.

06What you bring

There is nothing to upload and no file to hand in. You present the work. Bring these four things to your review slot.

  1. A working laptop. It needs Codex installed, the TradingView app logged in, your prospectus files on disk, your ChromaDB folder built, and your backtest script ready to run. The review runs on your machine.
  2. Five slides. Give one slide to each part, one to the numbers table and one to what broke. Do not bring more than five.
  3. Your prompt log. Keep the prompts you used, in the order you used them, open in a file you can show. AI use is expected on this assignment. Hiding it is the problem, not using it.
  4. Every member of the group. The review cannot start with a member missing.

07The live review — two hours

The faculty reviews every group in person. The session runs for two hours and splits in half.

Hour one — you code in front of us

  • Open your own project on your own laptop and work on it while we watch.
  • Expect a change request on the spot. Example: swap the momentum lookback from 12 months to 6 and rerun, or add a fourth question to the RAG bot, or point the MCP connection at a symbol outside your universe.
  • Use Codex during this hour. That is the point of the course, and it is not cheating here.
  • We are watching whether the group can steer the tool, read the error and fix the thing. We are not watching whether you can type from memory.

Hour two — you demonstrate

  • Run the MCP live and redraw your chart while we watch, then read the last traded price and its timestamp off it.
  • Answer two prospectus questions the faculty picks, and open the cited page to prove the answer.
  • Show the backtest output at all three cost levels and state the verdict on the target.
  • Every member of the group speaks. A silent member costs the group the live review mark.

What loses marks

  • A number on a slide loses its mark when nobody can trace it back to an output file.
  • A backtest that enters on the same bar as its signal scores zero on Part 3.
  • A citation that points at the wrong page fails that answer.
  • A live API key that appears on screen costs the whole Part 1 mark.
  • A group where only one member can explain the code loses the demonstration mark.
Reporting a failure correctly is worth full marks. If the MCP server never connected, show the error and what you tried. If the RAG bot could not find the promoter table, say which page it should have found and why it missed. If the strategy lost money, report the loss. The course marks the quality of the evidence, not the size of the return.
