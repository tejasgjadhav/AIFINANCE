Momentum Backtest in Codex

We type one English sentence into Codex. Codex writes a research plan, asks for approval, then builds and runs a momentum backtest on two years of NSE data in front of the class.

One sentence → Codex asks 3 questions → Codex writes a plan → we approve → the backtest runs → a monthly return table

01The sentence we typed

We want to run a Momentum strategy on last two year NSE data with a goal that we get monthly returns above 5%.

That is the whole brief. There is no code in it and no data attached. It carries a goal, a market, a window and a target. Module 4 calls this the goal. Everything Codex does next is the loop.

02What Codex did before it wrote any code

  1. It checked the workspace. It ran one command to list the files and found no data and no code.
  2. It asked us three questions. It pinned down the strategy and the success criteria before planning.
  3. It searched the web for NSE data sources. It found the NSE historical reports and the reports catalogue, so the data pipeline is auditable.
  4. It called the target what it is. Codex wrote that 5% a month is an aggressive target and that the plan should treat it as a constraint to evaluate, not a return to promise.
  5. It wrote the plan and stopped. It asked "Implement this plan?" and waited. Nothing was built until we said yes.
The screen in class

03The plan Codex wrote

  1. Data. Download 36 months of NSE data ending at the latest completed session. The first 12 months form the signal. The final 24 months are the test.
  2. Universe. At each month-end, use the NIFTY 50 constituents that were actually in the index on that date, not today's list.
  3. Signal. Rank the stocks by 12-1 momentum: the return from 12 months ago to one month before the rebalance date.
  4. Portfolio. Hold the top five at 20% each. Long only, always fully invested.
  5. Timing. Use only month-end information for the signal, then trade at the next NSE session's open. Compute daily NAV and calendar-month returns.
  6. Data honesty. Use adjusted prices with documented corporate-action adjustments. If a stock lacks enough validated history, halt and flag the run instead of quietly substituting data.
  7. Costs. Run three scenarios: 25, 50 and 100 bps round trip, charged as 12.5, 25 and 50 bps on each buy and sell leg.
  8. Benchmark. Compare every run to the NIFTY 50 total return, with a price-return comparison kept for reconciliation.
  9. Outputs. One run configuration with the as-of date, data path, lookback of 12 months, skip of 1 month, holdings of 5 and the cost scenario. The run writes monthly holdings, ranks, turnover, trades, and gross and net NAV and return series.

04What you do in class

Approve the plan. Watch the run. Then read the monthly return table and count the months above 5%. Read the same table at 25, 50 and 100 bps and write down what costs take away. Compare the final line to the NIFTY 50 total return over the same 24 months.

The point of the lab. The 5% target survives or fails on data, not on the prompt. A backtest is a ceiling on what a rule can earn, never a promise. Codex said the same thing in its first paragraph, and that habit is the one to copy.
Do it yourself. Open Codex, paste the sentence from section 01 and read the plan it writes before you approve anything. Change one thing, such as holding ten stocks instead of five or skipping two months instead of one, and read how the plan and the monthly table change. If you have no Codex plan, paste the same sentence into any free AI chat and ask it for the plan only. Compare it to the one above.

05Where to go from here

Swap the universe to the NIFTY Next 50 and see whether the signal holds. Add a stop at a fixed drawdown and see what it does to the monthly table. Run the same brief with a mean-reversion rule instead of momentum and put the two tables side by side.
